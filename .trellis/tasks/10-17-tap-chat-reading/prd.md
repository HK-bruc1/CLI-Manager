# Tap 聊天式阅读

## 需求

用户在 `/tap/` 只能看到终端原生画面与纯文本阅读版，希望增加图示聊天产品一样的提问/回复阅读体验。
2026-10-17 用户要求继续推进；版本未指定，记录为 TEMP。

## 验收

- 会话始终提供清楚的「对话 / 终端」切换；终端纯文本重排不再被误认为聊天视图。
- 对话以右侧用户气泡、左侧 Markdown 回复展示；正文有适合阅读的行宽与段落间距，代码块具有语言、复制和折叠操作。
- 继续使用当前 CLI 会话与输入框；切换视图不会另起会话或丢草稿。
- 主机不支持、未绑定或记录缺失时说明原因；旧主机明确告知更新桌面程序后重连，不能凭终端画面猜造聊天记录。
- 设备能力在浏览器重连后刷新；迟到请求不影响其他账号/设备，后来的设备事件优先于旧 HTTP 回执。
- 续验反馈：安装版与开发版同时在线时可识别设备渠道和对话能力；新配对/上线的设备可通过刷新和推送发现。用户明确选择「先连接开发版验证对话」，保留旧安装版会话。
- 桌面/手机、浅色/深色、中英文均可用；时间仍为 24 小时制。

## 边界

沿用 Claude/Codex 精确绑定的记录、分页和原生输入路径。用户后续决定暂不迁移 ACP，授权补充工具调用、结果和已有思考内容；图片消息不在本次范围。

## 续增验收：执行过程

- Codex / Claude 的规范工具输入、结果和明文思考摘要进入 Tap；不导出系统、metadata、未知块、思考签名或加密字段。
- 过程区及每个工具/思考详情默认折叠，实时更新不自动展开；手动展开状态在同轮刷新后保留。
- 工具结果不作为新用户提问；仅按 call ID 关联输入与输出，缺失或跨页的调用不猜配，不推断成功状态。
- 旧主机返回纯正文仍可读，旧客户端不请求详情时保持正文协议；分页不漏消息，限制响应字节、分块数量与长输出并显示截断提示。
- 覆盖历史重放、实时更新、多调用、调用无结果/结果无调用、跨页、无正文思考、两种语言与小屏。
